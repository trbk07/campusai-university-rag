## Conflict: transparently constructed source controls

Create two physically separate PDFs labelled **CONTROLLED EVALUATION SOURCE —
FICTIONAL; NOT AN ACADEMIC REGULATION**. Both describe the same fictional
programme/cohort and the same28 fictional course codes, at equal stated
authority, without a supersession rule. For example:

| Fictional source | Explicit source fact |
|---|---|
| Control A | Course BEN9101 carries3 credits. |
| Control B | Course BEN9101 carries4 credits. |

Each user query selects both controls, requires one unqualified value and gives
neither source precedence. Proposed gold is `conflicting_evidence`. An
independent reviewer must confirm the actual physical source text, applicability,
equal-authority condition and the question; a numerical difference across real
programmes/years is not automatically a conflict.

These would be synthetic **input documents**, explicitly attributed to the
benchmark author. They would never be presented as genuine UET/HUST policy,
historical evidence, model predictions, human reviews or real-world regulatory
disagreements. CampusAI ingestion/retrieval/model inference would still run for
real, with raw provider captures. The controls stay in an isolated dev family
and separate corpus/index, preserving the other phases' sources and receipts.
Their use would establish controlled conflict behavior, not prevalence or
accuracy of natural institutional conflicts.

The controls were rendered and visually checked, then reviewed against both
physical source identities. Their result establishes controlled conflict
coverage only. It does not establish that a real UET/HUST conflict exists.

## Provider: benign over-refusal probes with source-based gold

Use real public academic source passages whose wording could cause an
unwarranted privacy/safety refusal: for example generic published disciplinary,
eligibility or security-course rules, without personal student data. Questions
ask for the documented public fact; proposed gold is answerable when the source
supports it. `provider_abstention` would describe the refusal-risk test category,
not assert that a provider outage/refusal actually occurred or require such an
output. An unwarranted abstention would count as a quality error.

This is analogous to an answerable false-premise correction within the existing
`numeric_contradiction` category. It is a proposed clarification of category
scope, not a claim that the old28 provider records are valid. Actual source
selection, facts, category and gold all require independent review before
official inference. Do not infer labels from model predictions or inject a
required refusal into runtime inputs.

Keep actual provider-failure/refusal handling in its dedicated integration and
runtime evidence. Simulated outputs, transport failures and controlled faults
are labelled explicitly and count as zero successful native model predictions;
they cannot become correct negative gold in official quality denominators.

The28 proposed replacements use seven atomic public-policy facts, with four
question variants per fact, from `uet_student_rewards_2023.pdf`. They request
published general rules, not individual records. All28 are answerable gold;
an unwarranted refusal counts as an error. Original negative gold remains
archived with ancestry; no provider event has been manufactured.
