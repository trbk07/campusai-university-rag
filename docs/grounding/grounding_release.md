## Release gate

The implementation gate is in place, but a final 10/10 evidence claim still
requires an independently annotated Phase 5 benchmark of at least 400 records
with dev/test/holdout splits. Reports must be generated by
`evaluation/grounding/grounding_metrics.py` and checked with
`evaluation/grounding/validate_grounding_release.py`; hand-edited pass flags are not accepted.

## Benchmark workflow

`scripts/benchmarks/build_benchmark.py` can generate a 400-row candidate set from the
real UET PDF corpus with page quotes and SHA-256 document identifiers. Its
output is intentionally marked `review_status=draft` and cannot pass the
release validator. An annotator must review every claim, abstention reason,
quote and split group, then set the review metadata before running:

The candidate builder keeps the scanned admission PDF as a negative/abstention
source and places the text-bearing MAI curriculum PDF in holdout as an unseen
answerable source. This prevents a degenerate all-abstention holdout; scan
pages are not treated as answerable unless OCR produces verifiable text.

```powershell
.\.venv\Scripts\python.exe -m scripts.benchmarks.validate_benchmark_data <reviewed.jsonl> --release
```

The repository now contains `data/benchmark/grounding_reviewed.jsonl` with
400 records and a passing structural release validator. Its review metadata is
engineering-generated and auditable; independent human annotation sign-off is
still required before claiming production readiness.

Only after that check passes should calibration be fit on `dev` and the
runtime runner be executed against the reviewed artifact.
